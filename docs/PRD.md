## 1. 제품 개요

### 1.1 한 줄 정의
사용자가 직접 쓴 일기를 에이전트가 읽고 문맥을 파악해 심화 질문을 던지고, 답변으로 일기를 풍부하게 완성하며, 일정·회의록·운동기록 등을 외부 앱에 자동 저장하는 **개인 생산성 향상 에이전트 웹앱**.

### 1.2 문제 정의
- 일기를 쓰면 "오늘 뭐 했다" 수준에서 끝나 디테일이 남지 않는다.
- 하루 동안 발생한 정보(지출, 회의 내용, 운동 기록, 내일 일정)가 여러 앱에 흩어지거나 기록되지 않는다.
- 회고(일기)와 계획(일정)이 분리되어 생산성 루프가 끊긴다.

### 1.3 해결 방식
1. **회고 심화**: 에이전트가 일기 문맥을 감지하고 구체적 질문으로 디테일을 끌어낸다.
2. **자동 구조화**: 답변에서 운동/회의/학습/지출/일정 데이터를 자동 추출한다.
3. **루프 연결**: "내일 뭐 할 거예요?" 질문 → 일정 등록 → 다음 날 리마인드 → 저녁 회고로 이어지는 **계획→실행→회고 사이클**을 만든다.
4. **외부 연동**: MCP로 Notion·Google Calendar에 자동 저장한다.

### 1.4 타겟 사용자
- 일기·기록 습관을 만들고 싶지만 꾸준히 못 하는 사람
- 회의록, 운동 기록, 지출을 따로따로 관리하는 데 지친 사람

## 3. 기능 요구사항

### F1. 홈 대시보드
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F1-1 | 날짜별 인사말과 "오늘 일기 쓰기" CTA를 표시한다 | P0 |
| F1-2 | 어제 등록한 "오늘 하기로 했던 일"을 체크박스 목록으로 표시하고 완료 토글할 수 있다 | P0 |
| F1-3 | 주간 통계(일기 작성일 수 / 회의록 수 / 등록 일정 수)를 표시한다 | P1 |
| F1-4 | 최근 일기 목록(날짜·제목·사진 수)을 표시하고 상세로 이동할 수 있다 | P0 |

### F2. 일기 직접 작성
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F2-1 | 자유 텍스트로 일기를 작성할 수 있다 (자동 저장: localStorage, 2초 디바운스) | P0 |
| F2-2 | 작성 중 에이전트가 활동(운동/회의/공부/지출/기타)을 감지해 해당 구간을 색상 하이라이트한다 | P0 |
| F2-3 | 사진을 다중 첨부하고 미리보기할 수 있다 | P1 |
| F2-4 | "다 썼어요" 버튼으로 에이전트 대화 단계로 이동한다 | P0 |

### F3. 에이전트 심화 질문
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F3-1 | 감지된 주제별로 원문 인용과 함께 심화 질문을 한다 (주제당 최대 2개) | P0 |
| F3-2 | 답변에서 구조화 데이터(운동/회의록/학습/지출)를 추출한다 | P0 |
| F3-3 | 대화 중 사진 첨부 시 관련 주제에 자동 연결한다 | P1 |
| F3-4 | 마지막에 반드시 "내일은 뭘 할 예정이에요?"를 질문한다 | P0 |
| F3-5 | 내일 계획 답변에서 일정을 추출하고 **확정/미정**을 구분한다 ("~할까 생각중" → 미정) | P0 |
| F3-6 | 일정 미리보기 카드에서 체크박스로 선택 후 등록할 수 있다 | P0 |
| F3-7 | 사용자가 답변을 건너뛰면 재촉 없이 다음 주제로 넘어간다 | P1 |

### F4. 일기 완성 (풍부화)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F4-1 | 원문 흐름을 유지하며 답변 디테일을 해당 문단에 자연스럽게 삽입한다 (삽입부 굵게 표시) | P0 |
| F4-2 | 사진을 관련 문단 아래 자동 배치하고 캡션을 단다 | P1 |
| F4-3 | 해시태그를 자동 생성한다 | P2 |
| F4-4 | "다시 꾸미기" / "직접 수정"이 가능하다 | P1 |
| F4-5 | 함께 저장되는 구조화 데이터 요약을 표시한다 | P0 |

### F5. 외부 연동 (MCP)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F5-1 | Notion MCP로 일기 본문 + 메타데이터를 저장할 수 있다 | P0 |
| F5-2 | Google Calendar MCP로 등록 일정을 동기화할 수 있다 | P1 |

## 5. 개발 단계 및 인수조건

| Phase | 내용 | 인수조건 |
|---|---|---|
| 1 | Aspire + web/api/agent 스캐폴딩 | Aspire 대시보드에서 3개 서비스 healthy |
| 2 | 일기 에디터 + 활동 감지 | "헬스장에서 운동했다" 입력 시 초록 하이라이트 |
| 3 | 인터뷰 에이전트 + 일정 등록 | "헬스장 갈까 생각중" → 미정으로 분류 |
| 4 | 작가 에이전트 + 완성 화면 | 원문에 없던 "80kg 5×5"가 해당 문단에 굵게 삽입 |
| 5 | MCP 연동 + 내보내기 | Notion 저장 시 페이지 생성 확인 |
| 6 | Azure 배포 + 정리 | 공개 URL에서 전체 플로우 정상 동작 |

> 각 Phase 완료 시 **다른 모델로 산출물 검증** 후 다음 단계 진행.

## 7. 성공 지표 (데모 기준)

- 일기 작성 → 질문 → 완성 → Notion 저장까지 **5분 내 시연 가능**
- 에이전트 질문이 일기 문맥과 무관한 경우 0건
- 미정 일정 분류 정확도 시연 시나리오 기준 100%
